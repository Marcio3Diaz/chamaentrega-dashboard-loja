# Supabase -> MySQL migration map

## Inventory captured

- 36 public tables
- 89 directly portable indexes
- 11 PostgreSQL partial indexes that need an API/generated-column equivalent
- Supabase RLS, Postgres functions/triggers, Auth, Realtime, Storage and Edge Functions remain active during this phase

## Migration rule

The live Supabase project is **not changed** in this phase. This branch only creates the MySQL target schema and documents what must move into the ChamaEntrega API.

## Service mapping

| Supabase today | MySQL architecture |
|---|---|
| PostgreSQL tables | MySQL 8 / InnoDB |
| UUID generated by Postgres | UUID generated by API |
| RLS policies | authorization middleware + service layer |
| RPC / PL/pgSQL | transactional API services |
| Realtime | WebSocket / Socket.IO or Redis pub/sub |
| Edge Functions | ChamaEntrega API workers/jobs |
| Supabase Auth | dedicated auth layer (decision pending) |
| Storage | object storage (S3/R2-compatible; decision pending) |
| FCM token tables | remain in MySQL; Firebase still sends push |

## Critical business logic to port before cutover

1. Delivery acceptance and max simultaneous route/batch limit.
2. Delivery status transitions and location confirmation.
3. Prepaid wallet reservation, release and capture.
4. Delivery payment creation/confirmation.
5. Courier/store private-network approval flow.
6. Push-token registration and idempotent notification dispatch.
7. Courier moderation/verification.
8. Platform commissions/subscriptions.
9. WhatsApp/Goomer/integration ingestion.

## PostgreSQL partial indexes requiring redesign

- `courier_delivery_batches_one_active_batch_per_courier` on `courier_delivery_batches`: `CREATE UNIQUE INDEX courier_delivery_batches_one_active_batch_per_courier ON public.courier_delivery_batches USING btree (courier_id) WHERE (status = ANY (ARRAY['open'::text, 'locked'::text]))`
- `courier_push_tokens_active_idx` on `courier_push_tokens`: `CREATE INDEX courier_push_tokens_active_idx ON public.courier_push_tokens USING btree (courier_id, is_active) WHERE (is_active = true)`
- `courier_support_tickets_delivery_idx` on `courier_support_tickets`: `CREATE INDEX courier_support_tickets_delivery_idx ON public.courier_support_tickets USING btree (delivery_id) WHERE (delivery_id IS NOT NULL)`
- `courier_verifications_submitted_idx` on `courier_verifications`: `CREATE INDEX courier_verifications_submitted_idx ON public.courier_verifications USING btree (submitted_at DESC) WHERE (submitted_at IS NOT NULL)`
- `deliveries_active_courier_mvp_idx` on `deliveries`: `CREATE INDEX deliveries_active_courier_mvp_idx ON public.deliveries USING btree (assigned_courier_id, status) WHERE ((assigned_courier_id IS NOT NULL) AND (status = ANY (ARRAY['accepted'::text, 'heading_to_pickup'::text, 'at_pickup'::text, 'heading_to_dropoff'::text, 'at_dropoff'::text])))`
- `delivery_chat_messages_unread_idx` on `delivery_chat_messages`: `CREATE INDEX delivery_chat_messages_unread_idx ON public.delivery_chat_messages USING btree (delivery_id, read_at) WHERE (read_at IS NULL)`
- `uq_platform_revenue_delivery_type` on `platform_revenue_events`: `CREATE UNIQUE INDEX uq_platform_revenue_delivery_type ON public.platform_revenue_events USING btree (delivery_id, revenue_type) WHERE (delivery_id IS NOT NULL)`
- `uq_store_orders_delivery_id` on `store_orders`: `CREATE UNIQUE INDEX uq_store_orders_delivery_id ON public.store_orders USING btree (delivery_id) WHERE (delivery_id IS NOT NULL)`
- `uq_store_orders_source_external` on `store_orders`: `CREATE UNIQUE INDEX uq_store_orders_source_external ON public.store_orders USING btree (store_id, source, external_order_id) WHERE (external_order_id IS NOT NULL)`
- `uq_store_wallet_delivery_completed_debit` on `store_wallet_transactions`: `CREATE UNIQUE INDEX uq_store_wallet_delivery_completed_debit ON public.store_wallet_transactions USING btree (reference_type, reference_id, transaction_type) WHERE ((transaction_type = 'delivery_payment'::text) AND (status = 'completed'::text))`
- `idx_whatsapp_conversations_active_order_id` on `whatsapp_conversations`: `CREATE INDEX idx_whatsapp_conversations_active_order_id ON public.whatsapp_conversations USING btree (active_order_id) WHERE (active_order_id IS NOT NULL)`

## Checks not automatically translated

- `delivery_location_points.latitude`: `latitude >= '-90'::integer::double precision AND latitude <= 90::double precision`
- `delivery_location_points.longitude`: `longitude >= '-180'::integer::double precision AND longitude <= 180::double precision`
- `delivery_location_points.accuracy_meters`: `accuracy_meters IS NULL OR accuracy_meters >= 0::double precision`
